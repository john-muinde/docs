---
title: "Validate Mobile Money Account"
openapi: "POST /api/v3/customer/validate/mobile-money"
---

Checks a mobile money recipient before you pay them: the phone number format,
the country it belongs to, and whether that corridor is supported.

If your account is enabled for **name lookup**, the response also carries the
name actually registered on the number (`accountName`) and `nameLookupStatus`.
Without that entitlement you still get the format and corridor checks, and
`nameLookupStatus` comes back as `NOT_ENABLED` — the request is identical either
way.

Send `accountName` with the name you expect on the account and the response adds
a `nameMatch` block scoring it against the real one, so you can catch a wrong
number before the money moves.

## Paybill and till

Set `accountType` to `paybill` or `till` and send `shortCode` instead of
`phoneNumber` to validate an M-PESA business shortcode. For a paybill you can
also pass `accountReference` — the value a payer would enter as the account.

Because a shortcode is just digits, there is no useful format check for it: its
existence is exactly what the lookup answers, so these two types require the
name lookup entitlement.
